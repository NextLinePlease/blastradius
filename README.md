# BlastRadius

A safety check for software deployments that predicts failure probability, estimates downstream blast radius, and recommends a rollout plan for a simulated microservice fleet.

## Scope

All data is simulated. Services, traffic, and faults are generated by this project's own load generator and chaos injector.

Labels must be derived from injected faults and measured downstream impact, not randomly assigned.

## Problem Statement

In a microservice architecture, a failure in one service can propagate to its dependent services.

A deployment that appears safe in isolation can introduce failures across multiple services.

BlastRadius aims to analyze these dependencies, estimate deployment risk, identify potentially affected services, and recommend safer rollout strategies.

## Installation and Setup

### Prerequisites

- Windows with WSL2 and Ubuntu, or a Linux environment
- Docker Desktop
- Docker Compose
- Git
- Python 3

### Clone the Repository

```bash
git clone https://github.com/NextLinePlease/blastradius.git
cd blastradius
```

### Start the Microservice Environment

Build and start the containers:

```bash
docker compose up --build -d
```

Check running containers:

```bash
docker compose ps
```

View container logs:

```bash
docker compose logs -f
```

### Verify the Services

Check a microservice health endpoint:

```bash
curl http://localhost:8000/health
```

Retrieve the service dependency graph:

```bash
curl http://localhost:8080/dag/
```

### Run the Load Generator

Create and activate the Python virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Install the required dependencies:

```bash
pip install -r service/requirements.txt
```

Run the load generator:

```bash
python load_generator.py
```

*Run commands from the project root. The required services must be running before executing integration tests.*
